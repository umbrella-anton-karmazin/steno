# AGENTS.md

## Назначение
Этот файл задает правила разработки и взаимодействия для участников, работающих над Steno.
Правила проектные и применяются ко всем изменениям в этом репозитории.

## Контекст продукта
Steno — это desktop-приложение для macOS (PyObjC + rumps), которое:
- записывает встречи (экран/системный звук + микрофон);
- обрабатывает записи через ИИ и создает файлы протоколов;
- управляет артефактами встречи (`.mp4`, `_mic.m4a`, `_protocol.txt`).

## Архитектура
Текущая структура:
- `app.py`: координатор приложения, жизненный цикл, меню, high-level состояние.
- `recorder.py`: низкоуровневый native pipeline захвата (`ScreenRecorder`).
- `steno/config.py`: константы, дефолты, сохранение/загрузка конфига.
- `steno/i18n.py`: определение локали + flat YAML переводчик.
- `steno/services/permissions_service.py`: обертка системных API разрешений macOS.
- `steno/services/recording_service.py`: orchestration старта/остановки записи.
- `steno/services/processing_service.py`: AI-пайплайн и генерация протокола.
- `steno/services/meetings_service.py`: список/rename/archive/delete записей.
- `steno/ui/permissions_window.py`: окно первого запуска для разрешений.
- `steno/ui/main_window*.py`: main window, разделенный на view/state/actions.
- `assets/i18n/*.yaml`: ключи переводов.

## Базовые принципы
- Держать решения простыми и читаемыми.
- Не добавлять абстракции “на вырост” (YAGNI).
- Переиспользовать существующую логику (DRY), но не дробить код без реальной пользы.
- Не менять поведение приложения без явной задачи.

## Правила PyObjC (критично)
- Подклассы `NSObject` должны экспонировать Objective-C selectors прямо в финальном классе.
- Если логика разнесена по mixin-ам, selector-обертки должны оставаться в конечном `NSObject` классе.
- Для методов AppKit delegate/dataSource (`NSTableView`, меню, окна) нельзя полагаться только на mixin-методы.
- Все UI-изменения делать в main thread (`run_on_main` / `AppHelper.callAfter`).
- Блокирующие операции нельзя выполнять в main thread.

## Правила потоков и состояния
- Долгие операции (`AI upload/process`, потенциально блокирующие permission-запросы) запускать в background thread.
- Обновлять состояние приложения централизованно и после этого рефрешить UI.
- Соблюдать lock-состояния:
  - нельзя модифицировать запись во время записи или обработки;
  - нельзя запускать новую запись во время обработки.

## Соглашения по файлам и именам
- Базовая сущность записи: `<name>.mp4`.
- Связанные файлы:
  - микрофон: `<base>_mic.m4a`
  - протокол: `<base>_protocol.txt`
- В заголовках UI обычно показывать base name без `.mp4`.
- В строке файлов показывать реальные имена файлов с расширением.

## Правила i18n
- Все пользовательские строки должны идти через `tr("...")`.
- Новые ключи добавлять одновременно в `assets/i18n/ru.yaml` и `assets/i18n/en.yaml`.
- Имена ключей должны быть стабильными и сгруппированными по фичам (`main.*`, `menu.*`, `record.*` и т.д.).

## Правила конфига
- Сохранять конфиг только через `ConfigManager.save`.
- Новые ключи добавлять в `DEFAULT_CONFIG` в `steno/config.py`.
- Сохранять обратную совместимость с уже существующими конфигами.

## Runtime-пути
- Каталог записей по умолчанию: `~/Movies/Steno`.
- Конфиг приложения: `~/.recorder_app_config.json`.
- Логи приложения: `~/Library/Logs/Steno/app.log`.
- Файловые соглашения:
  - видео: `<base>.mp4`
  - микрофон: `<base>_mic.m4a`
  - протокол: `<base>_protocol.txt`

## Запуск и сборка
Запуск из исходников:
```bash
./.venv/bin/python app.py
```

Проверка синтаксиса:
```bash
python3 -m py_compile app.py steno/**/*.py
```

Сборка (только по явному запросу):
```bash
python3 setup.py py2app
```

## Правила взаимодействия
- Не собирать и не подменять `/Applications/Steno.app` без явного запроса пользователя.
- Не использовать разрушительные git-команды (`reset --hard`, checkout чужих изменений).
- Если появились неожиданные несвязанные изменения, остановиться и уточнить дальнейшие действия у пользователя.

## Чеклист валидации изменений UI/поведения
- Приложение стартует из `.venv`.
- Окно onboarding разрешений открывается, кнопки работают.
- Главное окно остается отзывчивым.
- Start/Stop записи работает, файлы создаются.
- Действия контекстного меню (rename/archive/delete) работают корректно.
- Process создает `_protocol.txt` и правильно обновляет UI-состояние.
- RU/EN переводы подхватываются корректно.
